# 长篇小说阅读页面 - 逻辑功能整理

## 一、页面概述

长篇小说阅读页面（`ReadPage`）是 app 的长篇小说核心阅读页面，采用"封面信息 + 热门书评 + 正文阅读"的单列表结构。页面通过 `Get.put` 配合 tag 持久化 Logic 实例，支持主题切换时 State 重建而不丢失已加载章节状态。

**路由参数：**
- `story_id`（必填）- 书籍 ID
- `story_title`（必填）- 书籍标题
- `initial_comment_id`（可选）- 从消息页跳转时传入的评论 ID

## 四、核心功能逻辑

### 4.1 页面初始化流程

```
initState()
├── 注册 WidgetsBinding observer（监听横竖屏切换）
├── 初始化 Logic（Get.put + tag 持久化）
│   ├── 初始化滚动控制器
│   ├── 初始化字号（从持久化读取，默认 18）
│   ├── 初始化自动阅读速度（从持久化读取，默认 0.2）
│   └── 清空之前的小说数据
├── 设置 show_navigation = false
├── 设置 can_apply_chapter_mutation 回调
├── 校验 story_id（无效则跳转首页）
├── 注册滚动监听 _handle_scroll
├── _init_with_progress_restore()（初始化并恢复阅读进度）
├── 处理 initial_comment_id（自动打开评论区）
├── 监听 FCM 推送评论导航事件
├── 检查是否需要恢复滚动位置（主题切换后）
└── 监听错误状态（自动返回上一页）
```

### 4.2 数据加载流程

```
fetch_info()
├── 检查 Store 缓存（避免重复加载）
├── 设置 is_loading = true
├── 调用 API: novel/get_info
├── 保存 NovelInfo 到 Store
├── 初始化点赞/收藏状态
├── fetch_directory()（获取章节目录）
│   └── 调用 API: novel_chapter/inquire
├── _fetch_chapter_content(0)（加载第一章正文）
│   ├── 内存缓存检查
│   ├── 磁盘缓存检查（7 天有效期）
│   └── 网络请求：get_chapter_content()
├── 设置初始内容到 Store
├── _preload_adjacent_chapters(0)（预加载第二章到缓存）
└── 设置 is_loading = false
```

### 4.3 阅读进度恢复流程

```
_init_with_progress_restore()
├── 未登录 → 直接 fetch_info()
├── 已登录 → 查询阅读记录 get_last_read_record()
├── 有进度 → 进入静默恢复模式
│   ├── 显示吐司"正在恢复阅读进度"
│   ├── fetch_info()（加载章节列表）
│   ├── _resolve_restore_chapter_index()（解析目标章节）
│   │   ├── 优先按 chapter_id（数据库 ID）匹配
│   │   ├── 其次按 chapter_no（章节序号）匹配
│   │   └── 最后用全书百分比推算
│   ├── _resolve_restore_chapter_progress()（解析章节内百分比）
│   │   ├── 优先使用 chapter_offset（后端保存的章节内百分比）
│   │   └── 其次用全书百分比反推
│   ├── jump_to_chapter(target_index)（跳转到目标章节）
│   ├── 退出恢复模式，设置 has_started_reading = true
│   ├── _wait_until_reading_layout_ready()（等待布局稳定）
│   ├── _scroll_to_chapter_progress()（滚动到章节内百分比位置）
│   └── 更新进度显示
├── 无进度 → 正常展示
└── 启动定时保存定时器（每 10 秒）
```

### 4.4 章节管理机制

#### 滚动窗口模型
- **不一次性加载所有章节**，而是维护一个"已加载窗口"
- 窗口范围：`[min_loaded_chapter_index, loaded_chapter_index]`
- 用户滚动到边界附近时自动加载上一章/下一章

#### 加载下一章（load_next_chapter）
```
load_next_chapter()
├── 防重入检查（is_loading_next）
├── 边界检查（是否已加载完所有章节）
├── _fetch_chapter_content(next_index)（获取正文，优先缓存）
├── _wait_until_chapter_mutation_allowed()（等待滚动空闲）
├── Store.append_chapter_content()（追加到正文列表）
├── 更新 loaded_chapter_index
├── _preload_adjacent_chapters()（预加载更后面的章节）
└── 记录加载完成时间（防抖）
```

#### 加载上一章（load_prev_chapter）
```
load_prev_chapter()
├── 防重入检查（is_loading_prev）
├── 边界检查（是否已到第一章）
├── 防抖检查（冷却 500ms）
├── _fetch_chapter_content(prev_index)（获取正文，优先缓存）
├── _wait_until_chapter_mutation_allowed()（等待滚动空闲）
├── 记录旧滚动位置
├── Store.prepend_chapter_content()（插入到正文列表头部）
├── 更新 min_loaded_chapter_index
├── jumpTo(old_offset + delta)（恢复滚动位置，实现无缝向上加载）
└── _preload_adjacent_chapters()（预加载更前面的章节）
```

#### 跳转到指定章节（jump_to_chapter）
```
jump_to_chapter(index)
├── 设置 is_jumping_chapter = true（显示骨架屏）
├── _rebuild_reading_window_around_chapter(index)
│   ├── 计算窗口范围：[index-1, index+1]
│   ├── 逐章 _fetch_chapter_content()（获取正文）
│   ├── Store.cache_chapter_content()（写入缓存）
│   └── Store.rebuild_reading_items_from_cache()（重建正文列表）
├── 更新 min_loaded_chapter_index 和 loaded_chapter_index
├── jumpTo(0)（重置滚动位置）
├── 设置 is_jumping_chapter = false
└── _preload_chain_after_jump()（预加载前后各 2 章到缓存）
```

### 4.5 缓存策略

#### 内存缓存
- 由 `NovelReadingStore` 管理，key 为章节索引
- 章节内容、小说详情均缓存

#### 磁盘缓存
- **目录**：`{systemTemp}/read_chapter_content_cache/`
- **文件名**：URL 编码后截取前 180 字符 + hashCode
- **有效期**：7 天
- **读取顺序**：内存缓存 → 磁盘缓存 → 网络请求

#### 预加载策略
- 阅读第 N 章时，提前预加载 N±2 章到缓存
- 跳章后预加载目标章前后各 2 章
- 预加载只写缓存，不修改正文列表

### 4.6 滚动事件处理

```
_handle_scroll()
├── 跳过条件：恢复滚动位置中、跳章冷却期、进度恢复冷却期
├── 标记用户已参与阅读
├── 导航栏显隐逻辑（非程序化滚动时）
│   ├── 接近顶部 300px → 强制隐藏导航栏
│   ├── 向下滚动超过 8px → 隐藏
│   └── 向上滚动超过 8px → 显示
├── 更新章节内进度（基于布局位置计算）
├── 计算全书阅读进度
├── 检测"上滑开始阅读"胶囊显隐
├── 自动加载上一章（距正文顶部 < 2.2 屏）
├── 自动加载下一章（距底部 < 2.2 屏）
├── 实时更新当前阅读章节索引
└── 确保当前章节的下一章已拼接
```

### 4.7 点击翻页功能

#### 三段式点击区域
- **上 1/3 区域**：上翻一屏
- **中 1/3 区域**：切换导航栏显隐
- **下 1/3 区域**：下翻一屏

#### 翻页实现
```
scroll_page_up() / scroll_page_down()
├── 计算翻页距离 = 视口高度 - 50px（预留底部）
├── 计算目标偏移量（clamp 到合法范围）
└── animateTo()（320ms，easeInOut 曲线）
```

#### 限制条件
- 正文区块必须贴近顶部（`is_reading_section_at_top`）才允许点击翻页
- 程序化滚动期间不触发导航栏显隐

### 4.8 导航栏显隐逻辑

#### 自动隐藏规则
- **接近顶部 300px**：强制隐藏导航栏，上滑不显示
- **向下滚动超过 8px**：隐藏导航栏
- **向上滚动超过 8px**：显示导航栏（仅远离顶部时生效）

#### 手动切换
- **点击正文中 1/3 区域**：切换导航栏显隐

#### 动画效果
- 顶部导航栏：`AnimatedPositioned`（300ms，easeInOut）
- 底部导航栏：`AnimatedPositioned`（300ms，easeInOut）

### 4.9 阅读进度计算

#### 全书进度计算
```
calculate_reading_progress()
├── 基于章节字数计算
├── words_before_chapter = 前面所有章节字数之和
├── chapter_read_words = 当前章节字数 × 章节内百分比
├── read_words = words_before_chapter + chapter_read_words
└── progress = (read_words / total_word_count) × 100
```

#### 章节内进度计算
```
_calculate_current_chapter_progress_from_layout()
├── 获取当前章节标题的滚动偏移量
├── 获取下一章标题的滚动偏移量
├── chapter_scroll_extent = 下一章偏移 - 当前章偏移
└── progress = (current_offset - chapter_start) / chapter_extent × 100
```

### 4.10 阅读进度保存

#### 定时保存
- 每 10 秒自动保存一次
- 保存内容：`novel_id`、`chapter_id`、`chapter_offset`（章节内百分比）、`read_progress`（全书百分比）

#### 退出保存
- dispose() 时同步保存一次

#### 保存条件
- 用户已登录
- 非加载中、非恢复中
- 进度恢复完成后 500ms 冷却期后才开始保存

### 4.11 横竖屏切换处理

```
didChangeMetrics()
├── 检测视口尺寸是否真正变化
├── 记录当前滚动比例
├── 设置 needs_restore_scroll_position = true
└── 下一帧执行 _restore_scroll_position_after_layout()
    ├── 优先使用像素级恢复
    ├── 像素偏移过大时使用比例恢复
    └── jumpTo(target_offset)
```

### 4.12 主题切换处理

- Logic 实例通过 `Get.put + tag` 持久化，State 重建后找回原有实例
- 主题切换后通过 `reading_store.needs_restore_scroll_position` 触发滚动位置恢复
- 背景色使用 `AnimatedContainer` 实现 300ms 过渡动画

## 十一、关键设计决策

### 11.1 Logic 持久化
- 使用 `Get.put(Logic(...), tag: story_id.toString())` 持久化 Logic 实例
- 主题切换导致 State 重建时，Logic 实例不丢失，已加载章节保留
- `ScrollController` 由 Logic 管理，跨 State 重建保持

### 11.2 滚动窗口模型
- 不一次性加载所有章节，维护 `[min_loaded, max_loaded]` 窗口
- 窗口大小通常为 3 章（跳章时）或逐步扩展（自然阅读时）
- 预加载只写缓存，不修改正文列表

### 11.3 章节拼接时机
- 章节内容可以提前请求和缓存
- 但真正 append/prepend 到 reading_items 必须等待滚动空闲
- 避免在拖动/惯性滚动中改变 ListView 高度导致卡顿

### 11.4 上一章无缝加载
- prepend 上一章后，记录旧滚动位置
- 下一帧计算新增高度 delta
- jumpTo(old_offset + delta) 保持视觉位置不变

## 十二、错误处理

- **详情加载失败**：设置 `is_error = true`，监听器自动返回上一页
- **章节正文加载失败**：返回空字符串，不影响页面展示
- **点赞/收藏失败**：乐观更新后回退状态，静默处理
- **预加载失败**：静默处理，用户真正滚动到时仍会正常加载
- **横竖屏切换**：记录滚动比例，下一帧恢复到相近位置

## 十三、2026-07 阅读流畅度优化后的约束

以下规则覆盖本文前面关于固定冷却时间、全局 Store 和跳章顺序的旧描述：

1. `ReadPage`、`Logic`、`NovelReadingStore` 和 `ScrollController` 一一对应，并跟随当前阅读路由释放；不同小说不得共享章节窗口。
2. 书籍详情与最后阅读记录并行请求。恢复进度时，目标章节完成真实布局和精确定位前始终保留骨架屏。
3. 所有目录、上下章和进度条跳转统一走章节事务：递增事务版本、并行加载目标窗口、重建列表、等待目标锚点、直接定位、更新进度，最后结束事务。
4. 连续跳章时只有最后一次事务可以修改章节窗口和结束加载状态；过期请求仅允许写入章节缓存。
5. 章节请求按索引复用正在进行的 `Future`，避免预加载、自然拼接和主动跳转重复请求同一正文。
6. append/prepend 不再轮询固定毫秒数，而是等待主列表的 `ScrollEndNotification`；执行前必须再次校验章节窗口版本。
7. prepend 上一章前记录原列表顶部章节的真实屏幕坐标，布局后优先按同一锚点的真实位移补偿 offset；只有锚点尚未渲染时才回退到 `maxScrollExtent` 差值。
8. 当前章节识别必须先于章节内进度计算，并始终同步 `current_chapter_db_id`。
9. 全书进度、进度条拖动、目录目标章节和章节内百分比统一按章节字数换算，不按章节数量平均分配。
10. 滚动时正文树不得随每个像素重建；进度文字、渐变遮罩、开始阅读胶囊和底部进度条使用独立轻量通知器更新。
11. 正文只保留一层点击手势，避免父子 `onTapDown` 同时触发翻页。
12. 导航栏使用“当前方向起点 + 同方向累计距离”控制显隐；方向变化和程序化定位必须重置锚点，避免微小回弹造成闪烁。
13. 横竖屏与字号变化使用“章节索引 + 章节内进度”恢复位置，不使用当前局部窗口的总滚动比例。
14. 阅读进度只有在布局稳定且用户发生真实阅读行为后才能保存，初始化和章节事务期间禁止覆盖服务端记录。
15. 目录远距离定位使用估算位置、整体比例和真实 RenderBox 多阶段收敛；当前章节必须完整进入带安全边距的可视区域，定位按钮才隐藏。
16. 长篇和短篇共用 `showCommentSheet`。回复任意主评论或子回复时，共享组件根据真实键盘高度把目标回复保持在键盘上方的剩余可视区域。
17. 自动阅读到达当前窗口底部时等待下一章拼接后继续；用户真实拖动列表时立即退出自动阅读。
